# GameHub — поиск тиммейтов, команды и игровые события

Учебный проект МДК 09.01, команда 1.
Сервис помогает найти игроков по свободным часам, режиму игры и микрофону, собрать команду и записаться на игровое событие. После события участники оценивают друг друга — из оценок считается **надёжность** игрока (1–10).

Стек: HTML5, CSS3, JavaScript (без библиотек), PHP 8.1+, MySQL 8 / MariaDB 10.4+ (PDO).

## Запуск

### XAMPP / OpenServer
1. Скопировать папку `gamehub` в `htdocs` (XAMPP) или `domains` (OpenServer).
2. Запустить Apache и MySQL.
3. Открыть phpMyAdmin → вкладка «Импорт» → выбрать `database/gamehub.sql` → «Вперёд».
   Скрипт сам создаёт базу `gamehub` (старая база с таким именем удаляется).
4. Проверить подключение в `includes/config.php` (по умолчанию `root` без пароля, хост `127.0.0.1`).
   В OpenServer пароль обычно пустой или `root`.
5. Открыть http://localhost/gamehub/

### Без XAMPP (встроенный сервер PHP)
```bash
mysql -u root -p < database/gamehub.sql
cd ..            # папка, в которой лежит gamehub
php -S 127.0.0.1:8080 -t .
# открыть http://127.0.0.1:8080/gamehub/
```
Подключение можно задать переменными окружения: `GH_DB_HOST`, `GH_DB_NAME`, `GH_DB_USER`, `GH_DB_PASS`.

## Главный сценарий
Регистрация → анкета → поиск игрока (`players.php`) → карточка игрока (`player.php`) → «Создать команду и пригласить» (`team_edit.php?invite=ID`) → событие (`events.php` → `event.php`) → «Подать заявку» (`actions/event_apply.php`) → заявка сохраняется в `event_participants` со статусом `pending` → организатор принимает её → статус `accepted`.

## База данных (9 таблиц, все связи через FK)
- `users` — пользователи и роли (`user` / `admin`), пароль — `password_hash()` (bcrypt);
- `games` — каталог игр;
- `player_profiles` — анкета игрока (1:1 с `users`);
- `player_games` — игры игрока (M:N `users`–`games`);
- `teams` — команды, **основная сущность с полным CRUD**;
- `team_members` — участники, приглашения (`invited`) и заявки в команду (`requested`);
- `events` — игровые события;
- `event_participants` — заявки на события и участники (`pending` / `accepted` / `rejected`);
- `ratings` — оценки после событий, из них считается надёжность.

## Безопасность и проверки
- Все SQL-запросы — подготовленные (PDO, параметры `?`), эмуляция отключена.
- Пароли — `password_hash` / `password_verify`; после 5 неверных попыток вход блокируется на минуту.
- Каждая форма с действием защищена CSRF-токеном; выход тоже только через POST.
- Вывод экранируется `htmlspecialchars` (функция `e()`).
- Валидация двойная: в браузере (`assets/js/app.js`, атрибуты `data-*`) и на сервере (в каждом обработчике).
- Загрузка файлов: проверка размера и реального MIME через `finfo`, случайное имя файла.
- Ошибки не «роняют» страницу: общий обработчик показывает понятное сообщение, 403/404 — свои страницы.

## Адаптивность
